# ⚡ Realtime в Canvia

Как правки одного пользователя появляются у остальных без перезагрузки.

## Схема

```
мутация (REST) → сервер пишет в SQLite → шина событий → клиенты
                                                        ├─ SSE-стрим (локалка, мгновенно)
                                                        └─ long-poll (туннель, почти мгновенно)
```

Мутации по-прежнему идут обычным REST (с дебаунсом перетаскивания 300 мс).
Сервер после каждой успешной записи кладёт событие в шину — клиенты применяют
его точечно в Zustand, полного `loadState()` нет.

## Что транслируется

Плитки (создание/движение/удаление), связи, наряды, монтажники, бригады.
По событиям групп клиент перечитывает вкладку целиком (редко, зато консистентно
с привязками плиток).

## Что НЕ транслируется

**Обзор (камера/зум)** — личный у каждого, хранится в `localStorage`
(`canvia-camera`, по датам). Иначе у всех прыгал бы экран вслед за кем-то одним.
`tab_states` на сервере остался только реестром вкладок.

Конфликты решаются по last-write-wins — для доски планирования достаточно,
CRDT не используется.

## Транспорты (по приоритету)

1. **SSE** — `GET /api/stream?token=...` (токен в query, т.к. EventSource
   не умеет заголовки). Каждое событие с `id: <rev>` — при автореконнекте
   сервер дошлёт пропущенное по `Last-Event-ID` из кольцевого буфера
   (последние 200 событий). Heartbeat-сообщение каждые 25с.
2. **Long-poll** — `GET /api/poll?since=<rev>`: висит до первого события
   (макс. 20с) и отвечает обычным конечным JSON. Нужен сетям, где бесконечный
   SSE рвётся (туннели/прокси с буферизацией). Включается сам, если стрим
   не встал за 10с или молчит дольше 45с.
3. **Догон** — `GET /api/sync?since=<rev>` при возврате на вкладку браузера
   и появлении сети.

Перезапуск сервера меняет `epoch` — клиенты это видят и делают полный
`loadState()` вместо догона (буфер в памяти теряется).

## Индикатор в хедере

- 🟢 **LIVE** — стрим подключен, всё мгновенно
- 🟡 **SYNC** — работает long-poll (стрим недоступен), задержка минимальна
- ⚪ **OFF** — ничего нет, тапните — панель покажет причину и кнопку повтора

В панели также счётчики: полученных сообщений и текущей ревизии — удобно
проверять доставку («подвигай плитку — счётчик вырос?»).

## Нагрузка

В простое — один висящий запрос на клиента и ноль запросов. Трафик только
в момент правок. Вкладка `groups`/`orders`/`tiles` перечитывается целиком
только в редких случаях (новая чужая вкладка, событие группы, смена epoch).

## Файлы

- Сервер: `server/src/realtime.ts` (шина, счётчик, буфер), `server/src/routes/realtime.ts` (`/stream`, `/poll`, `/sync`)
- Клиент: `src/App.tsx` — блок `REALTIME (SSE)`: `startRealtime` / `stopRealtime` / `applyRemoteEvent` / `catchUpRealtime` / `refreshRemoteTab`
