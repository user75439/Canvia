# 🔧 Диагностика и решение проблем

## 📋 Быстрая диагностика

Перед тем как искать проблему, выполните эту проверку:

```bash
# Проверить статус сервера
powershell -ExecutionPolicy Bypass -File status.ps1

# Или вручную
curl http://localhost:5000/api/health
curl http://localhost:8080
```

## 🆘 Частые проблемы и решения

### 1. ❌ Ошибка: "Port already in use"

**Проблема:** Порт 5000 или 8080 уже занят другим приложением.

**Решение:**

```bash
# Найти процесс на порту 5000 (сервер)
netstat -ano | findstr :5000

# Найти процесс на порту 8080 (фронтенд)
netstat -ano | findstr :8080

# Посмотрите столбец PID (последний) и завершите процесс
taskkill /PID <PID> /F
```

**Альтернатива:** Измените порты в конфиге

```bash
# Сервер - отредактируйте server/.env
PORT=5001

# Фронтенд - отредактируйте vite.config.ts
server: {
  port: 8081
}
```

---

### 2. ❌ Серверные окна закрываются сразу

**Проблема:** Окна консоли открываются и сразу закрываются.

**Решение:** Запустите вручную чтобы увидеть ошибку

```bash
# Откройте PowerShell в папке проекта
cd server
npm run build  # Может быть ошибка в TypeScript
npm start
```

**Частые причины:**
- ❌ Node.js не установлен - [скачать](https://nodejs.org/)
- ❌ Ошибка в коде - проверьте `npm run build`
- ❌ Отсутствует файл `.env` - создайте по образцу `.env.example`
- ❌ Permissions - запустите как администратор

---

### 3. ❌ Не видны данные с другого устройства

**Проблема:** С другого компьютера не может подключиться к http://192.168.2.104:8080

**Решение 1: Проверьте IP**

```bash
# Узнайте правильный IP вашего компьютера
ipconfig

# Ищите строку:
# IPv4 Address. . . . . . . . . . : 192.168.X.X
```

**Решение 2: Проверьте сеть**

```bash
# Проверьте что оба устройства в одной сети
ping 192.168.2.104

# Должно ответить:
# Reply from 192.168.2.104: bytes=32 time=5ms TTL=64
```

**Решение 3: Отключите VPN**

VPN может блокировать локальный доступ. Отключите и попробуйте снова.

**Решение 4: Firewall**

Добавьте правило в файрвол (запустите PowerShell от администратора):

```powershell
New-NetFirewallRule -DisplayName "PROFI Server 5000" `
  -Direction Inbound -LocalPort 5000 -Protocol TCP -Action Allow

New-NetFirewallRule -DisplayName "PROFI Frontend 8080" `
  -Direction Inbound -LocalPort 8080 -Protocol TCP -Action Allow
```

**Решение 5: Проверьте CORS**

Отредактируйте `server/.env`:

```env
CORS_ORIGIN=http://localhost:8080,http://192.168.2.104:8080,http://192.168.X.X:8080
```

Замените `X.X` на ваш реальный IP.

### 4. ❌ База данных повреждена или не работает

**Проблема:** Ошибки вроде "database is locked" или "no such table"

**Решение: Полный сброс БД**

```bash
# 1. Остановите сервер
stop.bat

# 2. Удалите папку с БД
rmdir /s /q server\data

# 3. Запустите сервер
start.bat
```

БД пересоздастся автоматически с тестовыми данными.

**Если это не помогло:**

```bash
# Удалите node_modules и переустановите
cd server
rmdir /s /q node_modules
del package-lock.json
npm install
npm run build
npm start
```

### 7. ❌ "CORS error" при запросе к серверу

**Проблема:** Браузер блокирует запросы с ошибкой CORS

**Решение:**

Отредактируйте `server/.env`:

```env
CORS_ORIGIN=http://localhost:8080,http://192.168.2.104:8080
```

Перезапустите сервер:

```bash
restart.bat
```

---

### 8. ❌ Файлы фронтенда не обновляются (кэш)

**Проблема:** Старая версия приложения в браузере

**Решение:**

```bash
# Очистите кэш браузера (Ctrl + Shift + Delete)
# Или используйте hard refresh: Ctrl + F5
```

Или заново постройте фронтенд:

```bash
npm run build
npm run preview
```

---

### 9. ❌ Медленная работа приложения

**Проблема:** Лаги при движении камеры или перемещении плиток

**Решение:**

Это нормально для браузера. Используйте Chrome или Edge, они быстрее.

Отключите расширения браузера которые замораживают страницу.

---

### 10. ❌ "npm: command not found"

**Проблема:** Node.js или npm не установлены

**Решение:**

1. Скачайте Node.js с [nodejs.org](https://nodejs.org/)
2. Установите (выберите LTS версию)
3. Перезагрузите компьютер
4. Проверьте: `node --version` и `npm --version`

---

### 11. ❌ Индикатор realtime OFF (серый)

**Проблема:** Изменения других не прилетают сами

**Решение:**

1. Тапните по индикатору — панель покажет причину
2. Кнопка «Повторить» переподключает вручную
3. В инкогнито/приватном режиме стрим может не держаться — откройте в обычном окне
4. Проверьте, что сервер свежий (после `git pull` нужен рестарт `npm run dev` на сервере)

---

### 12. ❌ Индикатор realtime SYNC (жёлтый)

**Проблема:** Это не ошибка, а запасной режим (подробности: [REALTIME.md](REALTIME.md))

**Пояснение:**

Прямой стрим (SSE) недоступен из этой сети — обычно через туннель или
мобильный интернет. Обновления идут long-poll'ом почти без задержки.
Если хочется именно LIVE — проверьте ту же ссылку на десктопе в локалке:
LIVE там означает, что душит сеть/браузер телефона, а не сервер.

## 📊 Проверка диагностики

Используйте этот скрипт для полной проверки системы:

```powershell
# Сохраните это в файл diagnose.ps1

echo "=== ДИАГНОСТИКА CANVIA ==="

echo ""
echo "1. Проверка Node.js"
node --version
npm --version

echo ""
echo "2. Проверка портов"
netstat -ano | findstr :5000
netstat -ano | findstr :8080

echo ""
echo "3. Проверка сервера"
curl http://localhost:5000/api/health 2>$null
if ($?) { echo "✅ Сервер работает" } else { echo "❌ Сервер не работает" }

echo ""
echo "4. Проверка фронтенда"
curl http://localhost:8080 2>$null
if ($?) { echo "✅ Фронтенд работает" } else { echo "❌ Фронтенд не работает" }

echo ""
echo "5. Проверка БД"
if (Test-Path "server/data/profi-planner.db") {
  echo "✅ База данных существует"
} else {
  echo "❌ База данных не найдена"
}

echo ""
echo "=== КОНЕЦ ДИАГНОСТИКИ ==="
```

Запустите:

```powershell
powershell -ExecutionPolicy Bypass -File diagnose.ps1
```

## 📝 Логи и отладка

### Где находятся логи

```
logs/
├── server.log          # Основные логи сервера
├── error.log           # Только ошибки
└── access.log          # HTTP запросы
```

### Просмотр логов в реальном времени

```powershell
# Следить за основным логом
Get-Content logs/server.log -Tail 20 -Wait

# Или для Windows:
tail -f logs/server.log
```

### Отладочный режим сервера

```bash
cd server
DEBUG=* npm run dev
```

Это выведет много информации о работе сервера.

## 🔐 Безопасность при диагностике

**Не делайте:**
- ❌ Не публикуйте логи в интернет (могут быть токены)
- ❌ Не меняйте JWT_SECRET просто так
- ❌ Не открывайте порты во внешний интернет без VPN

**Всегда:**
- ✅ Используйте файрвол
- ✅ Меняйте пароли по умолчанию
- ✅ Проверяйте логи на ошибки

## 🆘 Если ничего не помогает

1. **Посмотрите логи:**
   ```bash
   cat logs/error.log
   ```

2. **Переустановите полностью:**
   ```bash
   # Удалить всё
   rmdir /s /q node_modules server/node_modules
   del package-lock.json server/package-lock.json
   rmdir /s /q server/data
   rmdir /s /q server/dist
   
   # Переустановить
   npm install
   cd server
   npm install
   npm run build
   ```

3. **Запустите в режиме разработки:**
   ```bash
   start-dev.bat
   ```
   
   Это выведет больше информации.

4. **Проверьте интернет:**
   Убедитесь что у вас есть доступ в интернет - может понадобиться для скачивания пакетов.
